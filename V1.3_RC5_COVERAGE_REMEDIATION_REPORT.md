Before changing production code, a regression was run through the real Storage::cost_records_between path against a temporary SQLite row:


The pre-fix test passed by reproducing the defect: the row parsed as Coverage::Complete and is_authoritative() returned true. This is the exact RC4 audit finding, including the provider-facing cost exposure.

## 3. Root cause

crates/usage-storage/src/lib.rs used substring classification equivalent to coverage_raw.contains("Complete"). Therefore arbitrary persisted strings containing an authoritative token could be upgraded to an authoritative enum. The same class of bug would also affect Partial if it were parsed by substring or fuzzy matching.

## 4. Exact fail-closed parsing contract

The storage boundary now uses one small exact parser, parse_persisted_coverage_exact:

- exactly "Complete" maps to Coverage::Complete;
- exactly "Partial" maps to Coverage::Partial;
- the existing exact non-authoritative persisted representations map to their existing variants;
- every other string maps to Coverage::Unknown.

The parser does not trim, lowercase, use contains, starts_with, ends_with, prefixes, suffixes, or fuzzy matching. The security invariant is now: an arbitrary persisted string cannot become authoritative unless it is exactly one of the two allowlisted authoritative representations.

## 8. Authoritative cost aggregation

persisted_coverage_parser_is_exact_and_fail_closed inserts production-shaped SQLite cost rows and reads them through Storage::cost_records_between:

~~~text

Unknown                 $20.00  non-authoritative
~~~

The authoritative total is exactly $1.50; the raw/local total remains $46.50.

The existing runtime regression provider_facing_totals_exclude_non_authoritative_usage_and_costs also passes. Runtime provider-facing totals filter by authoritative coverage and the existing account/product identity conditions, so malformed and other non-authoritative amounts cannot reach provider-facing totals, daily totals, or period totals.

## 9. Budget path

The real budget spend calculation now runs through the extracted production-shaped reported_spend_for_budget helper used by deliver_budget_notices.

The regression budget_spend_path_excludes_non_authoritative_rows proves:

- Complete $1.00 plus Partial $0.50 produces authoritative spend $1.50;
- high non-authoritative rows do not increase spend;
- with a $2.00 budget, remaining budget is $0.50 and no notice is emitted;
- canonical authoritative rows still trigger the existing notice when the budget is actually exceeded.

Malformed persisted coverage therefore cannot create a threshold notice, budget-exceeded state, or altered remaining budget.

## 3. Legacy Claude persistence root cause (§4)

Traced end to end:

```text
Claude quota result (Partial, synthetic-v1)
→ Snapshot{coverage} → snapshots.payload_json (no source_strategy /
  trust-version columns; only account/product + blob)
→ last_known_good → stale_view_from_lkg (rewrites freshness ONLY)
→ RefreshOutcome.snapshot → outcome_to_dto (coverage preserved)
→ ProviderDto → overview aggregates / tray selector /
  notification planner / app_snapshot cache
→ app_snapshot cache value (full AppSnapshot JSON, no version)
→ get_snapshot serves it UNCHANGED on restart
```

Notification planner state is memory-only and delivery dedup is
suppress-only, so no persisted notification trust exists. Tray pinned
selection reads the live snapshot. Settings/store hold no coverage.
The defect isTweets purely the stored enum flowing through five
load surfaces without any source-aware check.

## 4. Legacy trust remediation (§6–§10)

Option D (migration + defensive runtime guard), kept minimal:

- Migration 010 (`migrations/010_claude_trust.sql` +
  `migrate_claude_trust`): rewrites `snapshots.payload_json` rows
  and the `app_snapshot` cache value, downgrading claude-code
  `Partial` → `UnverifiedSemantics`. Generic JSON walk keyed on the
  `(provider/product/coverage)` triple — the minimal existing
  provenance (§7); no new columns, no new trust framework.
- Runtime guard `reclassify_legacy_claude_snapshot` in
  `stale_view_from_lkg`, plus `reclassify_legacy_claude_dto` in
  `outcome_to_dto` and on both `get_snapshot` cache paths.
- `Partial` keeps its global authoritative-but-incomplete meaning
  (official paginated costs still emit and test it). Only the
  claude-code triple — for which no validated authoritative contract
  has ever existed — is downgraded. Fail closed.
- Tray/notification/overview/aggregation code untouched: they keep
  consulting `is_authoritative()` only (§10, no provider-specific
  conditions duplicated).

## 7. Diagnostics leak root cause (§14)

The v2 sanitizer ran user/provider-controlled alias and warnings
through shape redaction. Redaction is the wrong contract for export:
`MyPrivateProject` and identity notes carry no email/path/token
shape, so nothing fired — by design of denylists, not by accident.

Methodology note for the next audit: do NOT verify provenance by
grepping short literals in release binaries — rustc/LLVM lower
short strings into 8-byte `movabs` immediates, so `schemaVersion`
or `claude_pty_no_boot` never appear contiguously (proven with a
minimal repro). Use long markers (`Claude legacy trust
reclassification` present), distinct hashes vs the stale rc1 DMG
(`d1e0c8…` vs `776479…`), mtimes, and deterministic rebuilds.

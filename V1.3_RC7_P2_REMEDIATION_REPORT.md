## 2. RC6-P2-01 reproduction

The failing opt-in test was run against the available logged-in Codex installation:

~~~text
USAGE_AI_LIVE_CODEX=1
cargo test --locked -p usage-providers --lib live_app_server_reports_verified_quota -- --ignored
~~~

At RC6 it failed with:

~~~text
live quota fetch: Parse { schema: "codex-account-identity" }
~~~

An independent production-equivalent probe using the same real scoped Codex root succeeded with availability=READY, non-empty quota, identity present, and Coverage::Complete. This isolated the failure to the test context rather than to the shipped production coordinator.

## 3. Root cause

crates/usage-providers/src/codex_appserver.rs constructed the ignored live acceptance test's FetchContext with local_root: None. Production resolves the product-scoped root from CODEX_HOME or the home-directory .codex fallback, scopes it through the host file boundary, and passes it to the strategy. The strategy uses that scoped root as the safe identity fallback when the App Server response does not provide the expected identity shape.

Consequently, the RC6 test did not exercise the same context as production and could not use the same safe fallback. This was a P2 release-evidence defect, not a demonstrated provider-facing data-integrity failure.

## 4. Minimal remediation

The live acceptance test now mirrors the production root-resolution path:

- resolve the descriptor's configured environment root or home-directory local directory;
- scope it with hosts.file_scope.scope_root and the same cancellation token;
- require a production-scoped root for the opt-in live probe;
- pass that root and token into FetchContext.

Only the test module in crates/usage-providers/src/codex_appserver.rs changed. No production strategy, coverage policy, storage schema, provider registry, scheduler, tray, notification, routing, migration, lockfile, or CI workflow was changed.

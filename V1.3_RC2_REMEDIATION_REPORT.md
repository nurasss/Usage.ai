## 2. P0 Claude trust root cause

Synthetic/unreconciled Claude quota reached authoritative surfaces
through one mapping: `ClaudePtyUsageStrategy` and
`ClaudeOAuthUsageStrategy` returned `Coverage::Partial` for
explicitly synthetic shapes (`unverified_window_set`,
`unverified_oauth_shape`), while central policy treats `Partial` as
authoritative (`is_authoritative() == true` → `allows_tray_metric()`
→ `allows_quota_notifications()`). Exact escalation points: tray
`primary_remaining`/`tray_metric`, notification `Planner`, overview
aggregates, and the DTO presenting PTY as the Claude primary without
a fallback flag. This is Master Spec §28 P0
("unverified data driving tray/notifications").

## 3. Trust fix (§3, §4)

`Partial` keeps its valid global meaning — *authoritative but
incomplete* — proven by the official OpenAI costs path (truncated
pages of a verified shape). It was NOT changed globally. Instead the
Claude mapping was fixed: both PTY and OAuth snapshots/payloads now
report `Coverage::UnverifiedSemantics` ("shape parsed, semantics not
reconciled"), which is non-authoritative by the untouched central
policy. Tray, notifications, overview, and the unverified UI banner
close automatically — no hard-coded condition in tray code. The
existing variant fit best, so no new variant was invented.

## 4. Claude PTY timeout root cause (§7, §8)

Production path audited end to end: allowlisted spawn → PTY
allocation → staged writes (`/usage`, then `/exit`) → bounded
ANSI-stripped reads → kill/reap. Findings:

1. **Primary cause — ambient credential promotion.** The shell
   exports a 6-char `ANTHROPIC_AUTH_TOKEN` placeholder. Under it,
   `claude auth status` reports `loggedIn:true`
   (`authMethod:oauth_token`) although no subscription exists (clean
   env: `loggedIn:false`). The gate passed on a fake login then drove
   into a session with no quota to show → bounded Network timeout.
   The audit's "real subscription login" was almost certainly this
   same env token (same host, same profile).
2. **Secondary hazard — blind typing.** The driver wrote `/usage`
   immediately after spawn. On a trust-gated host this can land
   inside a trust/approval dialog and auto-answer it. Never observed
   live, but structurally possible.
3. Real servers flush per message and speak one JSON object per
   line; the matcher skips unparsable fragment lines by design, so a
   fragmented responder starves id-matching until the caller budget
   (bounded, no hang, no fabrication).

Fixes: `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` are scrubbed from
every CLI child (closed removal allowlist; endpoint routing left
alone); staged single-deadline drive (paint required before typing,
trust-dialog abort, dead binary is `Unavailable` fast); caller-scaled
render budget. A fake login now degrades in ~2s instead of hanging
20s (live-proven).

## 6. Multi-profile quota behavior (§12–§14)

- **Codex custom roots:** `CODEX_HOME` is set per scope at spawn.
  Proven live: an empty root reports an empty account (no
  type/email, `requiresOpenaiAuth:true`) — never the default login.
  Identity-less accounts classify as `AuthenticationRequired`, never
  an empty success. A/B isolation proven through real spawns with
  per-root identities (`plus` vs `team`) and per-home records.
- **Claude custom roots:** `CLAUDE_CONFIG_DIR` is set per scope for
  both the auth gate and the drive (required explicit test:
  A/B isolation through the real forkpty backend with per-root
  plans `Alpha`/`Beta`). OAuth stays default-only: no per-profile
  scoped credential source exists, and inventing one would violate
  §11.5.
- **Spec position:** §11.5 forbids cross-profile credential use;
  per-profile quota with proven per-root auth satisfies it. A root
  without login honestly shows history + auth state ("quota
  unavailable for this profile" via `AuthenticationRequired`, never
  another profile's numbers). No browser cookies read, no token
  refreshed, nothing written back.
- **OAuth (§11):** §10.3.2 is conditional ("if a provider-owned
  endpoint is used") — unsatisfied (no verified URL/host/
  credential, all three banned to obtain). The ordered strategy
  tolerates dormant OAuth by construction (NotConfigured skip);
  proven by a coordinator-composition test (pty→oauth→jsonl attempt
  order, OAuth skipped, history serves).

## 7. Diagnostics export fix (§15–§17)

text renders from the allowlisted `SanitizedBundle`, and the JSON
file export serializes the same bundle (schema v2; v1 serialized raw
DTOs). Added email redaction (`[redacted-email]`) and home-path
redaction (`/Users/[redacted]`, `/home/`, `/private/`, `C:\`) on top
of the existing secret/PEM/label redaction. Tests: hostile alias +
warnings + import warnings (`alice@example.com`,
`/Users/alice/private/project`, `Bearer SUPERSECRET…`,
`sk-test-secret…`) through the production export path — none
survive; safe enums/numbers/timestamps/versions/latency preserved;
copy/export semantic equivalence asserted. Bare codenames without
secret/email/path shape pass through by design (user's own labels,
same as display) — documented, not silent.

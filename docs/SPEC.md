# Usage.ai — техническое задание

Версия 0.2 · 2026-09-07 (UTC) · статус: проект ТЗ, реализация не начата

Уточнения пользователя: Intel Core i5 («I5-8»), все перечисленные сервисы,
подписки и API, история, уведомления, несколько аккаунтов, OpenCode Zen.
Поддержка не должна зависеть от текущего тарифа пользователя. Эта версия
заменяет ограничения v0.1 на Apple Silicon, три сервиса и один аккаунт.

## 1. Цель

Личное меню-бар приложение для macOS: лимиты ИИ-подписок, расход API и
история использования в одной панели. Функциональный аналог UsagePal,
написанный с нуля под именем Usage.ai. Структура интерфейса максимально
близка к приложенному референсу; интерфейс на русском, тема следует системной.

Приложение наблюдает за использованием, но не отправляет запросы моделям,
не меняет тарифы и не переключает аккаунты в сторонних приложениях.

## 2. Область работ

**Полная v1 — весь запрошенный набор функций**
- Иконка в меню-баре (без иконки в Dock), панель под иконкой.
- Подключения: ChatGPT / Codex и OpenAI API; claude.ai / Claude Code и
  Claude API; Gemini / Antigravity и Gemini API; Z.ai; OpenCode Zen.
- Остатки квот, динамические окна и пулы, время сброса, название тарифа,
  баланс/кредиты — для тех показателей, которые возвращает источник.
- Токены, фактические списания и отдельно расчётная стоимость API.
- Локальная история и обзор «Сегодня / Вчера / 30 дней», разбивка по
  моделям, продуктам и аккаунтам; экспорт CSV/JSON.
- Несколько аккаунтов каждого поддерживаемого сервиса; независимые
  подключения, история, бюджеты и настройки уведомлений.
- Уведомления о порогах, подтверждённом восстановлении квоты, бюджете;
  оценка темпа расхода при достаточных данных.
- Автообновление по расписанию, ручное обновление, кэш последнего снапшота.
- Настройки: интервал, запуск при входе, порядок сервисов, тема, горячая
  клавиша, отображение выбранного остатка в меню-баре.
- Intel-сборка `.app/.dmg`; проверка обновлений приложения и установка
  только проверенных обновлений после настройки канала распространения.

Разработка по этапам не исключает историю, уведомления или мультиаккаунт
из полной v1. Подключение без источника реальных данных не считается готовой
интеграцией: допустимые ограничения фиксируются отдельно, а не маскируются
демонстрационными цифрами.

**Вне области**: Windows/Linux как пользовательские платформы, облачная
синхронизация, телеметрия, перехватывающий API-прокси, автоматическая покупка
кредитов, обход квот, работа с чужими аккаунтами. Apple Developer ID,
нотаризация и платные CI-ресурсы требуют отдельного решения.

## 3. Подтверждённые требования и открытые допущения

- Целевая архитектура: **Intel x86_64**, процессор Core i5; точная модель
  Mac и версия macOS пока неизвестны. По обозначению процессора нельзя
  определить установленную ОС или гарантировать совместимость.
- Минимальная версия macOS пока не зафиксирована. Её согласуют до первой
  установочной сборки и проверят с выбранными версиями Tauri и плагинов;
  прежнее ограничение «macOS 14+ / Apple Silicon» не применяется.
- Пользователь работает приложениями. Наличие конкретного CLI, его версии
  и сохранённой сессии проверяется при подключении, а не предполагается.
- OpenCode подключается как **Zen**. Go не является синонимом Zen и в
  текущий обязательный список не входит.
- Точные тарифы спрашивать не требуется. Название тарифа, доступные метрики,
  окна, квоты и пулы определяются по данным источника. Неизвестный новый
  тариф не должен блокироваться списком названий Plus/Pro/Max.
- Универсальность по тарифам не означает одинаковые возможности API:
  права аккаунта и доступность данных остаются ограничениями провайдера.
- Приложение для личного использования, без обязательного собственного
  сервера. Учётные данные вводятся только локально, не передаются в чат.

## 4. Стек

Рекомендуемый стек: **Tauri 2 (Rust) + Svelte 5 / TypeScript**.

- Ядро на Rust: HTTP — `reqwest`, Keychain — `security-framework`, парсинг —
  `serde`, планировщик — `tokio`, история — SQLite с миграциями.
- UI: Svelte 5 + Vite + TS, CSS-переменные (без UI-кита), иконки Lucide +
  брендовые SVG провайдеров.
- Tray, позиционирование панели, автозапуск, уведомления, горячая клавиша,
  updater — средствами Tauri и совместимых плагинов. NSPanel-интеграция
  проверяется на Intel до выбора конкретного стороннего плагина.

Причина выбора: UI, агрегацию и адаптеры можно проверять в Linux, а близкую
к референсу панель разрабатывать в браузере. SwiftUI + AppKit остаётся
хорошей нативной альтернативой, но здесь сохраняется Tauri из исходного ТЗ.
Intel поддерживается отдельной сборкой, а не сменой стека. Размер и расход
памяти измеряются; сравнения с Electron без замеров не являются требованиями.

Версии зависимостей фиксируются lock-файлами при реализации. Linux-тесты
не заменяют сборку и проверку WebKit, Keychain, tray и уведомлений на macOS.

## 5. Архитектура

```
┌──────────────── Usage.ai.app ─────────────────┐
│ Frontend (Svelte)  ⇄ IPC ⇄  Tauri core (Rust) │
│  Panel / History / Settings  ├ accounts       │
│                              ├ scheduler      │
│                              ├ SQLite / cache │
│  tray icon / menu            └ adapters ──────┼──▶ разрешённые API
└───────────────────────────────────────────────┘──▶ выбранные локальные источники
                                                  ──▶ macOS Keychain
```

Cargo workspace:

- `crates/usage-core` — аккаунты, capabilities, метрики, агрегатор,
  дедупликация, правила уведомлений. Без зависимости от Tauri.
- `crates/usage-providers` — отдельные адаптеры продуктов, API-клиенты,
  парсеры и обезличенные фикстуры; платформенное чтение отделено интерфейсом.
- `crates/usage-storage` — SQLite, миграции, инкрементальный импорт, экспорт.
- `src-tauri` — tray, панель, Keychain, планировщик, безопасные IPC-команды.
- `src` — Svelte-фронтенд. Браузерный demo-режим с явной отметкой
  «Демонстрационные данные»; без доступа к реальным ключам и без записи в
  пользовательскую историю.

Модель данных (концептуально; это не готовые объявления типов):

```text
Account       { id, provider_id, external_identity?, label, connection_ref?,
                lifecycle: Active | Disconnected | Archived }
Snapshot      { account_id, product_id, plan_label?, capabilities, metrics,
                observed_at?, fetched_at, connection_state, freshness, coverage }
Quota         { pool_id, window_id?, used?, limit?, remaining_percent?, unit,
                window_start?, resets_at?, window_kind }
UsageRecord   { account_id, product_id, billing_scope_id?, source_record_id,
                period_start, period_end, model?, token_counts, source, coverage }
CostRecord    { account_id, billing_scope_id?, source_record_id, period,
                amount_decimal, currency, kind: Reported | Estimated, source }
MoneyBalance  { account_id, amount_decimal, currency, observed_at }
```

- `capabilities` описывает доступные квоты, историю, биллинг и баланс.
  Отсутствующее поле — не ноль, не 100 % и не «безлимит».
- У каждой метрики и отчёта сохраняются источник, время наблюдения/получения
  и охват. Свежая квота не делает свежим запаздывающий финансовый отчёт.
- `connection_state`: готово / приложение не запущено / нужен вход /
  недостаточно прав / cooldown / неподдерживаемый источник / ошибка.
  Свежесть и полнота данных задаются отдельно от состояния подключения.
- Аккаунт, продукт, источник и реальный платёжный контур различаются.
  Список моделей сам по себе не определяет, у какого сервиса списаны деньги.
- Идентичность аккаунта проверяется после каждого изменения авторизации;
  новый активный аккаунт стороннего клиента не перезаписывает старую историю.
- `external_identity` — стабильный непривилегированный ID/fingerprint
  аккаунта с пространством провайдера и организации, не email, не строка
  токена и не имя локального профиля. Если идентичность подтвердить нельзя,
  автоматическое объединение запрещено.
- Проценты валидируются; деньги хранятся decimal, токены — целыми числами.
  Кредиты и разные валюты не складываются как одинаковые единицы.

Планировщик: отдельное задание на аккаунт и источник, ограниченный параллелизм,
отмена и таймауты. Квоты по умолчанию обновляются раз в 5 минут, финансовые
отчёты — раз в 15 минут или реже по требованиям источника. Учитываются
`Retry-After`, exponential backoff и jitter; ручное обновление не обходит
cooldown. После сна выполняется один актуальный запрос, не очередь пропущенных.
Сбой источника не блокирует остальные; кэш показывается с возрастом данных.

## 6. Провайдеры

Приоритет: документированный read-only API или поддерживаемый интерфейс
клиента → выбранные локальные данные → экспериментальная интеграция только
после проверки разрешённого способа доступа. Вход в приложение не равен
автоматическому разрешению читать его секреты. Подключение подтверждает
пользователь; ключ API при необходимости вводится в Usage.ai и хранится в
Keychain, не в конфигурации или чате.

Публичная документация подтверждает отдельные источники, но подключения на
Mac пользователя ещё не проверены. Старые внутренние URL, названия методов
и пути из v0.1 не считаются проверенным контрактом.

### 6.1 ChatGPT / Codex и OpenAI API

- **Codex:** проверить документированный App Server [1] установленной
  версии для авторизации и чтения квот. Локальные session-записи могут дать
  историю токенов и последний снимок лимитов; их схема проверяется отдельно.
- **ChatGPT:** отображать только квоты конкретной функции, полученные из
  подтверждённого источника. Показатель Codex не выдавать за остаток всех
  моделей, чатов и функций ChatGPT.
- **OpenAI API:** отдельный адаптер Usage [2] / Costs [8] организации, с нужными
  правами и областью проекта. Обычный ключ для генерации не считать
  достаточным доступом к административным отчётам.
- CLI, IDE и desktop не создают три независимых лимита, если источник
  подтверждает один аккаунт и общий пул. Разные аккаунты не объединяются.
- Название плана, размеры и длительность окон берутся из ответа. Значения
  5 часов / 7 дней не зашиваются как универсальные правила.

### 6.2 claude.ai / Claude Code и Claude API

- **Подписка:** отдельный адаптер квот claude.ai/Claude Code. Наличие только
  desktop-приложения не доказывает наличие Claude Code-сессии. На этапе 0
  требуется разрешённый источник квот для фактического способа входа.
- **API:** документированный Usage & Cost Admin API [3]; требуется Admin
  API key, сервис недоступен индивидуальным аккаунтам. Недостаток прав
  показывается явно, без утверждения, что расход равен нулю.
- Если доступен только локальный журнал запросов, показываются локальные
  токены и оценка стоимости с пометкой неполного охвата, не общий счёт API.
- Лимиты разных продуктов объединяются только при подтверждении общего
  пула источником. Дополнительные траты не приравниваются к цене подписки.
- Токены стороннего клиента не обновляются и не записываются обратно:
  при истечении требуется обновить вход в исходном клиенте. Это правило
  распространяется и на будущие версии, пока не появится отдельный
  поддерживаемый механизм авторизации Usage.ai.

### 6.3 Gemini / Antigravity и Gemini API

- Google AI Pro — известный пример тарифа, не ограничение списка планов.
- **Antigravity:** источник должен вернуть фактические модельные пулы,
  окна и остатки. Документация описывает квоты и их просмотр [4], но не
  подтверждает стабильность внутренних методов из прежнего ТЗ.
- Локальный интерфейс IDE допустим только после проверки протокола,
  авторизации и привязки к выбранному экземпляру/аккаунту. Если приложение
  закрыто, показываются кэш и причина отсутствия обновления.
- Работа при закрытом IDE — цель интеграции, но не обещание, что можно
  безопасно переиспользовать любой Google OAuth-токен.
- **Gemini-приложение** и **Gemini API** — отдельные источники. Google AI
  Pro не считается балансом Gemini API. Для API проверяются права проекта,
  доступ к usage/billing и задержка отчётности [9]; точный контракт — этап 0.
- Модель Claude внутри Antigravity относится к пулу Antigravity, а не к
  подписке claude.ai или счёту Anthropic API.

### 6.4 Z.ai

- Отдельно учитывать **GLM Coding Plan** и оплату обычного API.
- Официальный Usage Query Plugin [5] подтверждает возможность чтения
  квот Personal Coding Plan. Его актуальный интерфейс исследуется без
  выполнения запросов генерации; поддержка других планов проверяется,
  а не предполагается по одному примеру.
- Метрики, план, единицы и периоды берутся из ответа. Для API-баланса и
  фактических списаний требуется отдельный подтверждённый источник.
- Расход GLM через Zen не записывается как прямое списание со счёта Z.ai.

### 6.5 OpenCode Zen

- **Zen — подтверждённый вариант пользователя.** Это платёжный источник,
  не общий синоним локального клиента OpenCode и не подписка Go [6].
- Цель: баланс/кредиты, фактические списания, модельная статистика и лимиты,
  если они доступны через авторизованный интерфейс Zen. Наличие ключа для
  генерации не доказывает доступ к истории биллинга; контракт — этап 0.
- Данные локального OpenCode могут дополнить историю. При импорте сохраняются
  реальный provider/account и охват: это только наблюдаемые сессии данного
  клиента, не доказательство полного расхода Zen.
- Запрос Claude через Zen относится к расходам Zen; запрос через собственный
  ключ Anthropic — к Claude API. Повторное суммирование запрещено.

### 6.6 Несколько аккаунтов и тарифная независимость

- Добавление, переименование, отключение и удаление отдельных подключений.
  Ключи и кэш изолированы по аккаунту; удаление предлагает отдельно удалить
  локальную историю и никогда не удаляет аккаунт у провайдера.
- При сохранении истории остаётся архивная запись аккаунта без секрета и
  активных заданий. Повторное подключение связывается с архивом только после
  проверки внешней идентичности и подтверждения пользователем; совпадение
  названия профиля недостаточно. Полное удаление убирает и локальную историю.
- Локальный клиент может отдавать только один активный аккаунт. Для второго
  нужен отдельный поддерживаемый профиль/вход; копирование одного токена под
  двумя названиями не считается мультиаккаунтом. Ограничение показывается.
- Квоты и окна динамические. Тариф — отображаемая метка, не условие допуска
  к интеграции. Отсутствующая метка не скрывает доступные реальные метрики.
- Изменение тарифа обновляет capabilities и окна, не пересчитывает прошлую
  историю по новым правилам. Неизвестный формат ответа даёт диагностируемую
  ошибку, а не фиктивный остаток.

## 7. UI / UX

Панель ориентировочно 360 × 690 pt, открывается под иконкой меню-бара,
закрывается по клику вне панели или Esc. Высота ограничена рабочей областью
экрана, содержимое прокручивается, футер закреплён. Поведение NSPanel и ввод
с клавиатуры проверяются на целевой macOS, включая несколько мониторов.

Структура сверху вниз:

1. **Обзор использования** — вкладки «Сегодня / Вчера / 30 дней»,
   стековая полоса по моделям, легенда в две колонки (топ-4 + «Другие»),
   переключатель «Токены / Расходы», фильтр аккаунтов, экспорт. Единица и
   охват явно подписаны; фактическая стоимость не смешивается с оценочной.
   Если модель неизвестна, запись попадает в «Модель не определена», а не
   теряется из суммы. Разбивка по проектам доступна при наличии таких данных.
2. **Секции провайдеров** в порядке из настроек. Заголовок: иконка, имя, справа
   бейдж плана («Google AI Pro», «Plus», «Max 5x»). Карточка с метриками:
   - строка: название («Сессия», «Неделя», «Gemini Pro» …) + точка статуса;
   - подпись продукта и аккаунта: одинаковая модель может расходовать
     разные подписки или API-бюджеты;
   - прогресс-бар остатка (заполнение = остаток); маркер темпа только для
     фиксированного окна с известным началом и концом. Для rolling-окна или
     неизвестного начала линейный прогноз не рисуется;
   - под баром: слева «Осталось 86 %», справа «Сброс сегодня в 6:36» /
     «Сброс завтра в 14:00» / «Сброс 11 сент. в 23:50»; «Не начато» только
     при подтверждении источником, иначе «Время сброса неизвестно»;
   - Состояния карточки: загрузка (скелетон), ошибка (текст + «Повторить»),
     устарело («обновлено 12 мин назад» серым), нет прав, нет источника,
     нет записей за период. Отсутствие данных не выглядит как полный лимит.
3. **Футер**: слева «Перезапустить для обновления» (только когда обновление
   скачано и проверено), справа «Следующее обновление через 3 мин» (клик — обновить
   сейчас).

Левый сайдбар: иконки провайдеров (клик — прокрутка к секции, индикатор следует
за прокруткой), внизу экспорт и настройки. Быстрые настройки открываются
в панели; подробная история и управление аккаунтами — в отдельном окне.
Основная панель сохраняет структуру референса и не требует открытия окна.

Точка статуса: зелёная — остаток > 25 % и темп в норме; жёлтая — остаток ≤ 25 %
или подтверждённый расход опережает применимый темп на 15+ п.п.; красная —
остаток ≤ 10 % или лимит исчерпан; серая — данных нет / устарели. Цвет
дублируется текстом, все действия доступны с клавиатуры и имеют названия
для VoiceOver. Эти пороги — настройки интерфейса, не размеры квот провайдера.

Меню-бар: монохромная template-иконка; опционально текст — остаток выбранной
метрики («C 86 %»). Правый клик: «Обновить», «Настройки…», «Выйти». Клавиши:
⌘R — обновить, ⌘, — настройки, Esc — закрыть.

Локализация: все строки в `src/i18n/ru.json` (en — позже), даты через `Intl` с
локалью `ru-RU`. Тема: `prefers-color-scheme`, по умолчанию система, можно
зафиксировать. Цветовые токены для обеих тем.

Визуальная приёмка: при ширине 360 pt и высоте 690 pt сопоставить панель
с референсом в одинаковом масштабе. Проверяются левый сайдбар, обзорная
карточка, двухколоночная легенда, заголовки с бейджами, полосы остатка,
подписи сброса и закреплённый футер. Контрольные состояния: тёмная тема
с демонстрационным набором как в референсе, светлая тема, прокрутка всех
сервисов, несколько аккаунтов, длинные русские строки и отсутствие данных.
Эталонные скриншоты формируются при реализации; сейчас их ещё нет.

## 8. История, расходы и достоверность

- SQLite хранит снимки квот отдельно от событий использования и отчётов
  биллинга. Разность двух процентов остатка не превращается в число токенов,
  запросов или денег: квоты могут восстанавливаться и меняться.
- Источники истории: разрешённые отчёты API, поддерживаемый экспорт,
  выбранные локальные журналы Codex, Claude Code и OpenCode. Конкретные
  пути, версии схем и доступность данных Antigravity проверяются на этапе 0;
  не предполагается, что у каждого desktop-приложения есть одинаковые логи.
- Импорт инкрементальный, с контрольной позицией и идемпотентным ключом
  записи. Повторный запуск, ротация/усечение файла и повторные страницы API
  не удваивают расход. Содержимое разговоров не сохраняется.
- При первом подключении запрашивается доступная история за 30 дней.
  Если её нет, накопление начинается с подключения. Пропуски отмечаются;
  отсутствие локальных записей не доказывает отсутствие использования.
- Снимки, события и временные границы хранятся в UTC; день пользователя и
  интервалы «Сегодня / Вчера / 30 дней» вычисляются в выбранном часовом поясе
  с учётом DST. Несовпадающие интервалы отчёта не выдаются за точную разбивку.
- Срок хранения по умолчанию — 90 дней, минимум для обзора — 30 дней.
  Пользователь может экспортировать или очистить только данные Usage.ai.

**Экспорт истории и диагностика — разные форматы:**

- CSV/JSON истории: версия схемы, продукт, модель, период, локальный
  псевдоним аккаунта («Аккаунт 1»), метрики/единицы, фактическая или оценочная
  стоимость, валюта, источник и полнота данных. По умолчанию не включаются
  произвольные названия аккаунтов/проектов, email, внешние ID и личные пути.
- Диагностика: только версии приложения/адаптера, коды состояний, время
  проверки и перечень доступных типов метрик; без финансовой истории.
- Оба формата исключают ключи, cookie, OAuth-токены, тексты разговоров и
  сырые ответы API. Пользовательский экспорт остаётся личным файлом;
  финансовые данные не становятся публичными из-за обезличивания аккаунта.

**Три разных финансовых показателя:**

1. Фактический расход — суммы из отчёта провайдера с указанным периодом и
   задержкой обновления; предварительный отчёт не объявляется финальным счётом.
2. Расчётная стоимость — токены × версия таблицы цен, с учётом cache и
   других доступных типов тарификации; отдельная метка «Оценка». Цена модели
   у прямого поставщика не подставляется вместо цены Zen или другого шлюза.
3. Остаток баланса/кредитов и заданный пользователем бюджет — отдельные
   метрики. Цена подписки и условная стоимость токенов не считаются
   дополнительными фактическими списаниями.

**Защита от двойного учёта:**

- Дедупликация внутри источника — по аккаунту, источнику и стабильному ID
  записи/отчётного интервала. Исправленный отчёт обновляет запись.
- Между источниками учитываются платёжный контур и пересечение периодов.
  Организационный отчёт и его подмножества по ключам/проектам не суммируются.
  Авторитетный биллинг не складывается с оценкой тех же локальных запросов.
- Если связь не доказана, наборы показываются раздельно без фиктивной общей
  суммы. Для сопоставления нельзя использовать только имя модели.
- Адаптер различает общие и вложенные счётчики: cache/reasoning не
  прибавляются повторно к total, если источник уже включил их в него.
- В легенде доли считаются в одной единице и по явно выбранному набору
  данных. Проценты независимых квот нельзя суммировать в «общий лимит ИИ».

## 9. Настройки

Интервал квот (1 / 5 / 15 / 30 / 60 мин, с учётом минимума источника) ·
Запуск при входе · Аккаунты: подключить/отключить, порядок, названия ·
Меню-бар: иконка / иконка + %, выбор аккаунта и метрики · Тема: система /
светлая / тёмная · Язык (ru) · Уведомления, тихие часы и бюджеты по аккаунтам ·
Шорткат (по умолчанию ⌃⌥U, проверка конфликтов) · История и экспорт ·
Обновления приложения.

Настройки и база: `~/Library/Application Support/Usage.ai/`. Ключи — только
в Keychain; в базе и настройках хранятся непривилегированные ссылки на них.
Файлы доступны текущему пользователю. Переименование аккаунта не меняет
его идентификатор и не смешивает историю с другим подключением.

## 10. Уведомления

- Пороги использования квоты по умолчанию 80 / 90 / 100 %, настраиваемые.
- Бюджет: сумма, валюта, период и источник — фактический расход или
  явно выбранная оценка. Задержка отчётности видна пользователю.
- Темп — прогноз с пометкой оценки, только при достаточных свежих данных
  и подходящем типе окна. При смене тарифа/пула прогноз пересчитывается.
- Сброс окна подтверждается новым наблюдением провайдера: истечение
  локального таймера само по себе не доказывает восстановление лимита.
- Дедуп по аккаунту, метрике, порогу и окну сохраняется после перезапуска.
  Старые данные, повторные запросы, сон/пробуждение и задний импорт истории
  не вызывают лавину уведомлений. Поддерживаются тихие часы.
- Отказ в разрешении macOS не мешает мониторингу; состояние показано в UI.

## 11. Безопасность и приватность

- Явное согласие на подключение конкретного источника. Нет массового
  сканирования Keychain, browser cookies или всего домашнего каталога.
- Собственные секреты Usage.ai — в Keychain. Ключи не возвращаются из
  хранилища в UI, не попадают в БД, логи, экспорт, crash-report или фикстуры;
  поля первичного ввода очищаются после сохранения.
- Предпочитаются минимальные read-only права. Если API требует широкого
  Admin-ключа, до подключения показываются его полномочия и риск; обычный
  ключ нельзя молча повышать до административного.
- Чужие файлы, профили и OAuth-сессии только читаются с разрешения;
  их refresh-токены не ротируются. Отказ в Keychain-доступе обрабатывается
  как состояние подключения, без требования «Всегда разрешать».
- Сеть ограничена проверенными адресами каждого включённого адаптера и
  отдельным каналом обновлений. Секреты не пересылаются на другой host при
  редиректе. Мониторинг не делает платных запросов генерации.
- Локальные интерфейсы ограничены loopback и проверенным экземпляром
  приложения; используется его штатная авторизация. Нельзя отключать TLS
  для всего localhost: самоподписанный сертификат требует привязки к
  конкретному проверенному экземпляру, иначе источник считается недоступным.
- CSP и Tauri capabilities запрещают произвольный shell, чтение файлов и
  внешнюю навигацию из WebView; удалённый контент не исполняется в панели.
- Для диагностики используется whitelist полей. Тексты запросов/ответов,
  токены авторизации, email и личные пути не экспортируются. Перед передачей
  диагностического отчёта пользователь видит его содержимое.
- Удаление подключения удаляет собственный секрет Usage.ai, но не ключ
  или сессию исходного приложения. Отозвать ключ у провайдера можно отдельно.

## 12. Нефункциональные требования

Цели для первого Intel-профилирования, а не уже подтверждённые показатели:
открытие панели из кэша ≤ 250 мс (p95), холодный старт ≤ 2 с, средний CPU в
простое < 1 % одного логического ядра за 5 минут без импорта. Память измеряется
вместе с WebKit-процессами; бюджет фиксируется после прототипа на целевом Mac.

Скрытая панель не анимируется непрерывно. Импорт ограничен по памяти и
не блокирует интерфейс. Сбой одного аккаунта не ломает другие, повреждённая
запись не останавливает весь импорт. Миграции БД транзакционные, перед
изменением схемы создаётся локальная резервная копия без секретов.

## 13. Тестирование и CI

- Парсеры: разные тарифы, неизвестный тариф, новые/отсутствующие поля,
  динамические пулы, некорректные проценты, неизвестное время сброса.
- Агрегатор: одинаковые записи из нескольких импортов, перекрытие отчётов,
  Zen против прямого API, cache/reasoning, разные валюты, DST, неполные сутки,
  отсутствие данных против нулевого расхода, смена тарифа и аккаунта.
- Планировщик/уведомления: 401/403/429, `Retry-After`, offline, частичный сбой,
  истёкшая сессия, сон, повторный старт, неподтверждённый сброс, тихие часы.
- Хранилище: миграции, восстановление после прерывания импорта, удаление
  аккаунта с историей и без неё, переподключение архива, смена активного
  аккаунта клиента, изоляция секретов. Проверяются отдельные whitelist-схемы
  экспорта истории и диагностики, отсутствие запрещённых полей в обеих.
- UI: светлая/тёмная тема, все состояния, длинные названия, несколько
  аккаунтов, маленький экран, навигация с клавиатуры. Demo-проверки в браузере
  не считаются проверкой интеграций с настоящими аккаунтами.
- План CI (Linux): форматирование, clippy и unit-тесты переносимых Rust-crates;
  TypeScript/Svelte check, тесты UI и production build.
- План CI (macOS): нативные тесты и сборка `x86_64-apple-darwin`, проверка
  архитектуры итогового executable. Runner выбирается с явной поддержкой
  Intel; ARM-only артефакт не считается подходящей сборкой.
- Весь CI использует только обезличенные фикстуры, моки и отдельные тестовые
  записи Keychain. Личные API/Admin-ключи, cookie, OAuth-сессии и хранилища
  пользователя не загружаются в CI или артефакты. Ключи подписи релиза —
  отдельная категория, настраиваемая лишь после согласования выпуска.
- Версия SDK, минимальная macOS и версии плагинов фиксируются совместно [7].
  Стоимость/квоты CI проверяются перед включением, без обещания бесплатного
  macOS-runner или конкретного количества минут.
- Ручная проверка на принадлежащем пользователю Intel Mac с его отдельным
  согласием, не в CI: установка, Keychain, реальное чтение каждого источника,
  tray/NSPanel/WebKit, разрешения уведомлений, автозапуск и обновление.

Сейчас существуют только требования: тесты приложения и эти CI-workflows
ещё не созданы и не выполнялись.

## 14. Сборка и дистрибуция

Форматы: `Usage.ai.app` и Intel `.dmg`, bundle identifier
`com.nurasss.usageai`. Сборка приложения macOS выполняется на macOS [7];
Linux-песочница не подтверждает работоспособность установщика.

Для личного прототипа допускается локальная/ad-hoc сборка. Ad-hoc подпись
не равна Developer ID и нотариальному заверению Apple: поведение Gatekeeper
зависит от версии macOS и происхождения файла. Не отключать Gatekeeper и
не удалять quarantine автоматически. Перед распространением выбирается и
проверяется безопасный способ установки; подпись Apple — отдельное решение.

Обновления: отдельный ключ подписи updater, проверка артефакта до установки,
сохранение совместимости с Intel и минимальной macOS, атомарная замена.
Закрытый репозиторий не требует встраивать GitHub-токен в приложение:
используется явно разрешённый канал или ручная установка. Пока канал не
настроен, updater отключён и не показывает ложное предложение обновления.

не является доказательством правильности.

## 16. Риски

- Недокументированный endpoint или схема клиента меняется → версионированный
  адаптер, фикстуры, безопасная ошибка без подмены метрик.
- Нет разрешённого API для потребительской подписки или Zen-биллинга →
  исследование/экспорт/локальные данные с явными ограничениями, не обещание
  скрытого универсального API.
- Нет Admin-прав или источник показывает только активный аккаунт → явное
  ограничение конкретного подключения, без обхода доступа.
- Локальная история неполна → индикатор охвата, без восстановления прошлых
  дней из догадок. Финансовый отчёт запаздывает → timestamp и статус.
- Чужой клиент ротирует токен → перечитать разрешённый источник или попросить
  обновить вход, не менять чужой refresh-токен.
- Несовместимая macOS/плагин/Intel-сборка → проверить в первом прототипе,
  а не в конце разработки. Точная версия macOS остаётся открытым пунктом.
- Gatekeeper и канал обновлений → отдельная проверка установки/подписи;
  не ослаблять системную защиту ради прохождения приёмки.

## 17. Идеи на потом

Английская локаль · Raycast / Stream Deck · Universal-сборка для Apple Silicon ·
Дополнительные сервисы, включая OpenCode Go · Виджеты. История, расходы,
уведомления и несколько аккаунтов уже входят в v1 и не относятся к этому списку.

## 18. Что ещё нужно перед реализацией и выпуском

- Версия **macOS**, не процессора: меню  → «Об этом Mac», строка macOS
  с названием и номером версии. Это нужно до первой установочной сборки,
  но не блокирует подготовку ТЗ. Intel и Zen уже подтверждены.
- На этапе подключения — версии приложений и доступные способы авторизации.
  Тарифы пользователя не нужны для проектирования; реальные возможности
  каждого подключения определяются автоматически, когда это позволяет API.
- До выпуска — способ установки и канал обновлений. По умолчанию никакой
  покупки Apple Developer, изменения видимости репозитория или оплаты CI
  без отдельного решения не происходит.

Код приложения, CI, диагностический скрипт и установщик в рамках этой
редакции ТЗ не создаются. Сначала согласуется технический план и ограничения
источников, затем начинается реализация по этапам.

## 19. Официальные источники и границы проверки

Документация просмотрена 2026-09-07. Она подтверждает описанные возможности
сервисов, но не заменяет проверку конкретной версии клиента, полномочий
аккаунта и подключения на Mac пользователя.

- [Codex App Server][1] — интерфейс интеграции с клиентом.

- [Claude Usage and Cost API][3] — административные права и ограничения доступа.

- [Gemini API Billing][9] — отдельный биллинг и уровни доступа к API.
- [Z.ai Usage Query Plugin][5] — квоты GLM Coding Personal Plan.
- [OpenCode Zen][6] и [отдельный продукт Go](https://opencode.ai/docs/go/).
- [Tauri 2: macOS application bundle][7] — сборка и настройки macOS.
